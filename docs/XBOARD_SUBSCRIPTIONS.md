# Xboard 多订阅节点对接约定

本文件交给面板开发方实施。此次只修改 V2bX 及安装升级脚本，不修改 web 面板源码、数据库、订单或机器人。
V2bX 内核依赖保持原锁定版本，订阅拆分不依赖内核升级。

## 兼容目标与边界

| 面板 | 节点 | 要求 |
| --- | --- | --- |
| 旧面板 | 旧节点 | 原有行为 |
| 旧面板 | 新 V2bX | 接口、鉴权、下发和上报 JSON 形状均保持原样；无需改节点配置 |
| 新面板 | 旧 V2bX | 面板继续实现下面的 UniProxy 兼容接口，id 统一输出 node_user_id |
| 新面板 | 新 V2bX | 同一协议；支持同一账号的多条独立订阅 |

“任意一端先升级”成立的前提是新版面板保留旧协议，不删除旧接口或要求旧节点新增字段。节点升级无法弥补面板对旧接口的破坏。
新 V2bX 没有新增必填配置、请求字段或必需的功能协商，已有账号照常使用。
本次不实现 WebSocket 客户端，也不修改 Xray / sing-box 底层。

## 三类 ID

- user_id：账号，负责登录、余额、返佣和 Telegram 绑定。
- subscription_id：面板订阅资产主键，负责套餐、到期和流量权益。
- node_user_id：节点身份，映射到一条订阅；通过旧协议中的 id 字段传输。

node_user_id 全局唯一、为正整数、永不复用，同一订阅在各节点上使用相同值。
兼容旧 32 位节点时，所有编号不得超过 2147483647。
续费、换套餐、流量重置都不重新分配这个编号。
每条订阅有独立 UUID / token；两条订阅不能共用 UUID。
请求参数 node_id 一直代表服务器节点，不能与 node_user_id 混淆。

节点只回传收到的身份编号，不需要知道账号、订单、订阅名称或订阅的数据库主键。
可以额外下发 user_id / subscription_id 供其他实现使用，但旧节点不能依赖它们，本版 V2bX 也不使用它们计费。

## 必须保留的 HTTP 接口

当前 V2bX 请求均携带原参数 node_id、node_type、token；保留其原鉴权方式。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/v1/server/UniProxy/config | 现有节点配置，保留 base_config.pull_interval / push_interval |
| GET | /api/v1/server/UniProxy/user | 按订阅筛选身份列表 |
| POST | /api/v1/server/UniProxy/push | 增量流量上报 |
| POST | /api/v1/server/UniProxy/alive | 在线 IP 上报 |
| GET | /api/v1/server/UniProxy/alivelist | 跨节点汇总在线 IP 数量 |

GET user 保留 ETag / If-None-Match：
- 304 表示列表未变，保留当前用户。
- 200 + {"users":[]} 明确表示列表为空，新节点会撤销全部旧身份。
- 错误、无法解析的响应不能伪装成空列表。
- 支持 JSON；若返回 application/x-msgpack，字段和含义必须与 JSON 一致。

## 下发示例

账号 42 拥有订阅 501、502；它们分别分配 node_user_id 90001、90002。

```json
{
  "users": [
    {"id":90001,"uuid":"11111111-1111-4111-8111-111111111111","speed_limit":100,"device_limit":2},
    {"id":90002,"uuid":"22222222-2222-4222-8222-222222222222","speed_limit":200,"device_limit":5}
  ]
}
```

筛选依据：账号未封禁、订阅已启用、未到期、剩余额度可用、该订阅权限组允许访问该节点。
将 subscription.node_user_id 映射成响应 id；其他字段从该订阅读取。
账号封禁移除全部订阅；单条订阅停用、到期、流量耗尽只移除自身。

## 上报示例

POST push 继续是 node_user_id 到 [上传增量字节, 下载增量字节] 的对象：

```json
{"90001":[1048576,2097152],"90002":[3145728,4194304]}
```

不能改成累计量、订阅数组或嵌套 subscription_id 对象。节点当前使用的流量单位和方向保持原样。
面板批量查询 node_user_id -> subscription_id / user_id 映射，对订阅入账，沿用节点倍率规则。
账号统计需要汇总所有订阅；订阅统计保留 subscription_id，不能把节点编号写入账号统计表的 user_id。

未知编号必须拒绝或记录异常，不能回退为 User::find(node_user_id)。
对曾经合法下发身份的迟到尾流量，仍应归原订阅；换组、到期或停用不能将它改记到别的订阅。
节点身份及其历史映射不要随订阅归档删除，避免尾流量失去归属。节点鉴权仍需校验，避免任意身份注入。

POST alive 保持同一编号体系：

```json
{"90001":["198.51.100.10"],"90002":["198.51.100.20","198.51.100.21"]}
```

GET alivelist：

```json
{"alive":{"90001":1,"90002":2}}
```

现有设备规则实际上按在线 IP 去重，并非物理设备识别；按订阅继续执行这套规则。
缓存建议使用 subscription_devices:<node_user_id> 等独立前缀，防止旧账号缓存和新身份混用。
在线 IP 数、限速、设备上限以及停用通知均以同一 node_user_id 为准。
保留旧字段 device_limit 的语义，不要将账号维度总数直接下发给每条订阅。

## 面板需改的位置

1. ServerService::getAvailableUsers：查询订阅并结合账号封禁，输出旧格式。
2. ServerService::processTraffic、UserService::trafficFetch、TrafficFetchJob：批量解析身份并对订阅入账；新队列载荷显式标记身份语义，避免与遗留任务混读。
3. StatUserJob / 统计模型：增加订阅维度，再按真实账号 ID 汇总；保留节点倍率和原统计口径。
4. DeviceStateService：所有 Redis 设备读写、在线数量、last_online_at 更新改为订阅维度。
5. CheckTrafficExceeded：检查订阅额度，只移除该订阅的节点身份。
6. NodeSyncService、NodeUserSyncJob、UserObserver 及新的订阅 Observer：覆盖订阅生命周期；账号变更展开到各订阅。事务提交后再派发同步。
7. 面板现有 V2 HTTP / WebSocket 的全量、增量、设备和停用消息共享同一序列化与身份解析逻辑；删除消息也必须携带 node_user_id。
8. 订阅地址生成：从订阅读取 token / UUID，适配目前 Server::generateServerPassword(User) 的账号类型约束，保证客户端凭据与节点下发匹配。

旧节点按拉取周期收到增删；不能把面板侧 WebSocket 实现当成本次 V2bX 已具备的能力。

## 迁移与切换

- 为每个旧订阅迁移一条资产，node_user_id = 原 user.id，保留 UUID / token / 到期 / 已用流量与额度。
- 新增身份从独立、并发安全的全局序列分配；起点超过所有迁移编号。此后新增账号也从同一身份序列分配，不能再直接拿新账号 ID 当节点身份。
- 不使用 MAX(id)+1 做并发分配；UUID、token、node_user_id 均有数据库唯一约束。
- 正式切换前处理完旧流量、统计和同步队列；新旧任务使用不同载荷版本或队列，明确区分账号 ID 与节点身份。
- 升级新映射时，已有连接的身份编号保持不变。尽量先发布兼容查询和上报适配，再开放多订阅购买入口。
- 使用新的订阅缓存空间；只有在流量任务完成、映射可用后才切换缓存与停用检查，避免原地重解释旧数据。
- 回滚面板时，在多订阅数据产生后不能直接退回仅支持 User 计费的版本；应保留兼容网关 / 上报映射。单独回滚节点仍走同一个协议。

## 本次节点改动

- 保持 UserInfo.id、uuid、speed_limit、device_limit 字段及 HTTP 路径原样。
- 比较用户变化时同时检查身份编号、UUID、限速和设备数限制；变化时替换内核用户与 limiter 条目。
- 区分 304 未变化和 200 明确空列表。
- MessagePack 响应缺失 users 时返回解析错误，不能意外清空节点。
- 在线设备上报失败正确返回错误；在线数接口不可用时保留原兼容降级方式。
- 严格解析完整 JSON / MessagePack 响应，拒绝截断、重复 users 成员、重复身份编号或 UUID；解析失败不更新 ETag。
- 限制变更保留对应身份的跨节点在线计数；内核应用失败时失效 ETag，尽力恢复旧身份并在下次拉取重试。
- sing-box 适配层将 UUID -> id 映射按本地节点隔离，移除某一节点的身份不会删除另一节点的流量归属。

## 联调验收

1. 旧面板 + 新节点：旧 ID、原 UUID、现有流量和在线设备均正常。
2. 新面板 + 旧节点：兼容接口不要求额外参数，一账号两订阅分别登录、扣流量。
3. 新面板 + 新节点：两订阅的流量、设备限制、限速互不影响。
4. 单独停用 A，B 保持可用；账号封禁时 A/B 都失效。
5. 续费 / 换套餐不改变节点身份；流量重置不转移已有尾流量。
6. 修改设备上限、限速、UUID 或 id 后，新节点正确替换对应用户。
7. 304 保持用户；200 空数组移除用户；HTTP / 解码错误不清空用户。
8. 两订阅同时上报、缓存失效、队列重试、到期尾流量和节点断线后均不串账。

现有流量机制仍有“读取后清零、请求失败可能丢批次”的限制，面板的队列批次去重不等同于 HTTP 重复请求去重。
本次不在旧面板上启用新的流量重放机制。未来如加可靠重试，必须协商批次 ID、明确 ACK 并由面板做请求幂等，不能直接重发不带批次号的流量。

## 配置保留升级

首次从 wyx2685 脚本切换，root 执行：

```bash
wget -O upgrade.sh https://raw.githubusercontent.com/ChampagneA7/V2bX-script/master/upgrade.sh && bash upgrade.sh
```

后续执行 V2bX update，或 V2bX update <自己的 Release 版本号>。
升级脚本只替换 /usr/local/V2bX/V2bX 和现有管理脚本，保留 /etc/V2bX、证书、geo 数据、service 文件以及开机自启设置。
仅使用 ChampagneA7/V2bX Release；不会因获取失败回退到原作者版本。
替换前下载并检查 SHA256、执行 version、备份原程序和管理脚本，并只读打包配置。
运行中的节点需要短暂重启；启动或运行检查失败时尝试自动恢复旧程序。升级前已停止的服务继续保持停止。
审查修复版新增 check-ready PID 命令，在内核、面板初始化和节点启动完成后记录运行态就绪状态。升级等待当前服务 PID 就绪，再持续检查存活与就绪；默认最多等待 180 秒，可用 V2BX_READY_TIMEOUT 指定 1 到 3600 秒。
运行态文件位于 Linux 的 /run/V2bX，不修改 /etc/V2bX 配置；无法记录就绪状态不会阻止节点服务运行，但升级脚本会拒绝判定升级成功。
程序和管理脚本来自同一个带 SHA256 的 Release 包；缺少配套管理脚本的旧包会在停止服务前退出。
服务停止或恢复失败时明确报告失败，不能把磁盘文件恢复误报为旧进程已恢复。业务验收仍需实际连接验证，升级包含短暂重启。
发布工作流只生成草稿，并要求填写审查过的 V2bX-script 完整提交号；公开发布需要另行确认。
